# RLCD 儿童音乐播放器设计

## 目标

让 Waveshare ESP32-S3-RLCD-4.2 在无触摸屏场景下播放 TF 卡儿童音乐、语音搜索并播放在线歌曲、按键控制播放，并把在线歌曲完整缓存到 TF 卡以便重复播放和断网播放。改动也要修正当前音乐链路中已确认的生命周期、资源分配和 UI 问题，并减少空闲耗电。

## 设备与现状

- 目标板为 Waveshare ESP32-S3-RLCD-4.2，IDF 6.0.2。
- 板载 TF 槽使用 SPI；原理图将 MOSI/SCK/MISO 分配到 GPIO21/GPIO38/GPIO39，片选网连接 GPIO17。
- 现有网关客户端能搜索、检查歌曲可用性并自动换源；应用层能流式解码 MP3/LRC，但没有 SD 曲库、缓存、暂停或曲目队列。
- 现有播放任务对解码 PCM 使用反复创建的 `std::vector`，且音乐停止/状态协调只覆盖单曲网络流。
- FATFS 当前生成配置是 ANSI/OEM 编码，不能可靠访问中文“儿童音乐”目录；要在 ESP32-S3 默认配置中启用 FATFS UTF-8 API 编码与长文件名。
- 官方板卡资料说明板载 CHG 灯显示充电状态；原理图中充电器 STAT 仅接 LED，没有接入 ESP32 GPIO。固件不能从此硬件读取准确的充电状态。

## 用户体验

- TF 卡按 FAT32 使用；音乐目录固定为 `/sdcard/儿童音乐/`，递归读取 MP3，忽略隐藏目录和非 MP3 文件。插卡前可创建该目录；目录不存在时给出明确提示，不自动格式化或改动用户卡片。
- KEY（GPIO18）：单击暂停/继续；双击下一首；长按上一首。没有本地曲目时，按键仍可控制当前在线歌曲；空闲时 KEY 单击仍可切换首页/音乐页。BOOT（GPIO0）继续用于对话/唤醒，不更改启动/配网行为。
- 语音工具提供本地儿童音乐播放、暂停/继续、下一首、上一首、停止，以及现有在线搜索/播放。播放本地目录时返回曲目名和曲库数量；无卡/无文件时明确告知用户。
- 在线歌曲首次播放时边下边播并写入缓存临时文件；只在 HTTP 正常结束且整个文件完整后原子改名为可用缓存。缓存命中先从卡播放，网关 URL 变化或断网不影响已缓存歌曲。
- 文件名以音源和歌曲 ID 生成稳定缓存键；没有稳定 ID 的 URL 以规范化 URL 哈希作为键。元数据保存在伴随索引文件中，不把未经验证的远程名称当路径。
- 缓存上限按固定字节数和卡片剩余空间双重约束；空间不足时按最近最少使用清理，跳过正在播放和 `.part` 文件。异常断电留下的 `.part` 在启动扫描时删除。用户儿童音乐目录与缓存目录分开，不删除用户音乐。

## 架构

- 在公共 Board 接口上增加可选 `MusicStorage` 能力；默认返回空，应用核心不依赖 RLCD 具体类、GPIO 或挂载点。
- RLCD 板创建 SDSPI/FATFS 实现，挂载 `/sdcard`，负责目录扫描、文件打开、原子缓存提交和 LRU 清理。挂载失败不影响语音助手启动与在线流播放。
- `Application` 继续负责跨协议的音频播放生命周期。播放源抽象为在线 URL 或本地文件，并统一处理解码、暂停/继续、跳过、停止、进度与清理。歌曲队列和状态由应用层的串行调度更新。
- 在线流读到的 MP3 原始字节写入 `.part`；解码和写缓存用固定大小缓冲区，播放结束时 flush/close/commit。停止、网络错误、卡被拔或写入失败时保留在线播放能力，丢弃不完整缓存。
- 播放器保留唤醒监听；空闲播放结束后关闭扬声器输出并恢复低功耗网络策略。缓存扫描只在启动/用户请求/将要写入缓存时运行，不周期轮询 SD 卡。
- 电量百分比继续显示现有 ADC 估算。若设备没有可信 USB/STAT GPIO，UI 显示电量但不伪造“充电中”；只有找到已连线的硬件信号才显示充电状态。板载 CHG LED 仍由充电芯片独立控制。

## 控制与 MCP 工具

- 增加工具：`self.music.local.play`、`self.music.pause`、`self.music.resume`、`self.music.next`、`self.music.previous`、`self.music.status`。
- `self.music.stop` 保持现有语义，停止本地或在线播放并清理任务。
- 现有 `self.music.search` / `self.music.play` 返回稳定缓存 ID，并建立在线播放队列；播放歌曲结束后若队列中有下一首才自动继续，不擅自开启连续播放。

## 空闲耗电

- 保持唤醒词与麦克风工作（用户已确认），继续在空闲时关扬声器功放。
- 音乐任务结束、失败和停止走同一清理路径，恢复 LOW_POWER，关闭 HTTP、解码器、重采样器、缓存文件和临时内存。
- 不做高频电量/卡扫描；反射式 LCD 仅在 UI 数据变化时刷新。

## 错误处理与安全

- SD 缺失、FATFS 挂载失败、中文目录不可见或文件格式不支持时，语音/按键给出中文反馈；网络音乐仍能播放。
- 只识别 `.mp3`（大小写不敏感）；其他格式暂不加入，避免解码器声明与实际支持不一致。
- 目录扫描有歌曲数上限，拒绝超深目录和超长路径，排序确定且稳定。
- SD 文件操作用互斥锁串行化；卡拔出或 I/O 错误不能卡住应用事件循环或音频任务。
- 仅在完整网络响应且至少有有效 MP3 解码数据时标记缓存完成。缓存清理仅删除播放器自己的缓存命名空间。

## 已识别的音乐链路问题

1. 播放流到 EOF 的判断把连续三次 0 字节读取当成完成，未区分已知 Content-Length 下的提前结束，可能把截断文件误当成功。
2. 解码循环遇到 `consumed == 0` 时跳出内层循环，但随后直接丢掉当前剩余输入，损坏跨读取边界的 MP3 帧。
3. 每个解码块都新建若干 PCM `std::vector`，在长音乐会造成堆分配/释放频繁，增加碎片与耗电。
4. 没有暂停/继续、曲目队列、播放状态查询或本地曲库，所以按键/语音无法可靠控制音乐。
5. 当前播放详情 API 不保留曲目 ID，无法让缓存跨网关流 URL 变化复用。
6. LRC 下载的 HTTP 状态处理需要和音频读取统一验证，失败时不应把错误响应显示成歌词。

## 验收

- IDF 6.0.2 的 RLCD 目标构建成功；通用接口变动同时构建一个无 SD 的代表目标，确认默认空能力不会破坏其它板。
- 主机侧测试覆盖缓存键、缓存完成/失败状态、清理候选选择、MP3 目录过滤和按键动作映射。
- 没插卡时正常启动、语音与在线音乐正常；插入 FAT32 卡后能读中文目录并播放；重复播放缓存歌曲时不产生网关音频请求；网络断开后仍能从缓存播放。
- 按键单击/双击/长按、语音暂停/继续/切换/停止不破坏唤醒和对话状态。
- USB 串口实测音乐结束、停止和失败时输出关闭，唤醒监听仍可用；外接电量计对比缓存播放与在线下载功耗。
- 如无法读取充电器状态 GPIO，在交付说明中明确屏幕不能准确显示充电状态，板载 CHG 灯可用于判断。
